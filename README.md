# Krisha Agent — мониторинг недвижимости в Алматы

Раз в день собирает новостройки (приоритет) с **Krisha.kz** и **Korter.kz**, а вторичку (по желанию) — с **Krisha.kz**, сравнивает цены, находит новые объекты и снижения цен, и присылает сводку в **WhatsApp**. Работает на **GitHub Actions** — без своего сервера.

## Как это работает

```
GitHub Actions (cron 09:00 Алматы / вручную)
  → сбор: Krisha-новостройки, Korter, Krisha-вторичка (если включена)
  → склейка дублей между площадками (один ЖК + комнаты + похожая площадь = один объект)
  → сравнение с data/state.json: что новое, где упала цена
  → Claude формирует сводку на русском → Green API отправляет в WhatsApp
  → если цена упала больше чем на 3% — отдельное немедленное сообщение
  → data/state.json и data/digest.json коммитятся обратно в репозиторий
```

Один запуск = один полный цикл. Если один источник упал или сменил вёрстку — это не останавливает остальные: ошибка попадёт в лог и будет упомянута в сводке, но вторичка/оставшиеся источники всё равно отработают.

Репозиторий **публичный** — в коде и в `data/*.json` нет ничего личного (только объявления и цены), а все ключи лежат в GitHub Secrets. Это позволяет любому фронтенду (например, `dastan-apps`) читать `data/state.json`/`data/digest.json` прямо по адресу `raw.githubusercontent.com` без какого-либо backend.

## 1. Настройка фильтров — `src/config.ts`

Все значения в `config.primary.*`/`config.secondary.*` — заглушки (`TODO`), заполни их под себя: районы, комнаты, площадь, бюджет, цена за м², срок сдачи, класс жилья. Соглашение:
- `0`/`null` в числовом поле-максимуме = без ограничения
- `[]` в массиве (районы/комнаты/классы) = без ограничения по этому полю

Первичка включена по умолчанию (`config.primary.enabled = true`), вторичка выключена (`config.secondary.enabled = false`) — включи вторым этапом, когда понадобится.

## 2. Секреты для GitHub Actions

В репозитории → **Settings → Secrets and variables → Actions** добавь:

| Секрет | Назначение |
|---|---|
| `MY_WHATSAPP` | твой номер (цифры с кодом страны, без `+`), куда приходит сводка и алерты |
| `ANTHROPIC_API_KEY` | ключ Claude API — формирует текст сводки |
| `GREEN_API_ID_INSTANCE` | из личного кабинета green-api.com |
| `GREEN_API_TOKEN` | из личного кабинета green-api.com |
| `GREEN_API_URL` | (необязательно) персональный хост инстанса |
| `DIGEST_WHATSAPP` | (необязательно) доп. номера для сводки через запятую |

Также один раз включи автокоммит результатов: **Settings → Actions → General → Workflow permissions → Read and write permissions**. Без этого шаг `git push` в конце workflow упадёт с 403.

## 3. Первый запуск

Запусти workflow вручную: вкладка **Actions → Scrape → Run workflow**. Это проверит весь цикл (установка Playwright/Chromium, сбор, сводка, коммит `data/state.json`) без ожидания расписания.

После первого успешного прогона `data/state.json`/`data/digest.json` появятся в репозитории и будут доступны по адресу:
```
https://raw.githubusercontent.com/<твой-аккаунт>/krisha-agent/main/data/state.json
https://raw.githubusercontent.com/<твой-аккаунт>/krisha-agent/main/data/digest.json
```

## 4. Локальный запуск (для отладки)

```bash
npm install
npx playwright install chromium
cp .env.example .env   # заполни ключи
npm start               # один полный прогон, без ожидания cron
```

## Расписание

Cron в `.github/workflows/scrape.yml`: `0 4 * * *` (04:00 UTC = 09:00 Алматы) + ручной запуск (`workflow_dispatch`) в любое время.

## Про селекторы парсера

Krisha.kz и Korter.kz периодически меняют вёрстку/структуру данных. Если какой-то источник начал возвращать 0 объектов — в логе запуска (Actions → последний прогон) будет видно, какой скрейпер упал и почему; обычно это означает, что нужно поправить селекторы в `src/scrapers/krishaPrimary.ts` / `korter.ts` / `krishaSecondary.ts`.

## Вежливость к сайтам

Между запросами — случайная пауза (`config.scraper.minDelayMs`–`maxDelayMs`), количество страниц ограничено (`config.scraper.maxPages`). Не увеличивай агрессивно без необходимости.
